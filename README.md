# 砺行（LiXing）

一个**按时段打卡 + 激励驱动**的 Android 学习自律应用，以长周期备考（考研）为原型。  
核心理念：**默认离线、零心智负担、打卡不超过 2 次点击、进度一眼可见。**

打卡/激励数据默认只存本机。联网仅在以下场景发生：用户主动使用「墨墨背单词同步」「百度网盘版本」，或用户在设置页开启「WebDAV 多端同步」后的自动同步（仅 Wi-Fi 可开关）；不会后台静默上传或覆盖数据。

## 构建

> 依赖仓库优先走阿里云镜像，可在国内网络直接拉取。

```bash
# 必须使用 JDK 17/21。AGP 8.13 不支持系统里常见的 JDK 25，
# 用错版本时 Gradle 只会甩一句 “What went wrong: 25.0.3”，极难看出是 JDK 的问题。
# JDK 路径写在 GRADLE_USER_HOME 下的 gradle.properties（不入仓库，各人机器不同）：
#   org.gradle.java.home=D\:\\tools\\jdk-21.0.12+8       # properties 里反斜杠需转义
# 或直接给环境变量：export JAVA_HOME=/path/to/jdk-21
./gradlew assembleDebug          # 出 app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest      # 运行全部单元测试
```

- `compileSdk 36`、`targetSdk 35`、`minSdk 26`
- Android SDK 路径在 `local.properties`（当前指向 `D:\Android\Sdk`）
- Gradle 8.14.3 / AGP 8.13.2 / Kotlin 2.2.21 / Compose + Material 3
- **本仓库开发机把 JDK 路径放在 `.gradle-local/gradle.properties`**（该目录已 gitignore），`docs/release.sh` 也用 `GRADLE_USER_HOME=F:/APP/.gradle-local` 构建，克隆后请按自己的 JDK 路径新建同名文件，不要提交进仓库
- 排查技巧：在 `GRADLE_USER_HOME/daemon/<gradle 版本>/*.log` 里 grep `javaHome=`，能看到历史构建实际用的是哪个 JDK
- **调试签名用项目内密钥库** `app/debug.keystore`（口令 android / androiddebugkey）：用户主目录的 debug 密钥库曾被清理工具删掉重建导致覆盖安装失败，现已固定进仓库，不要删除或替换它，否则已装设备无法覆盖更新

## 版本化备份

设置页「数据」支持生成可恢复的 `.lixingbackup` 版本包：

- 包含全部 Room 业务表、非敏感设置和仍存在的打卡照片；墨墨 Token、百度 OAuth 凭证不会写入备份；
- 每个版本带格式版本、数据库版本、创建时间、设备、任务/照片数量和 SHA-256 校验；
- 可通过 Android 系统文件选择器导出到文件或支持该选择器的网盘，并在另一台设备导入；
- 恢复前会校验文件与数据库版本，并自动保存一个 `before_restore` 本机恢复点；
- 可把数据库 v2～当前版本的历史包恢复到当前 schema；后续新增列使用数据库默认值，新表保持为空；
- 本机版本按设置中的保留数量轮转（默认 7 份）。

当前版本包尚未加密，不应放入公开共享目录。

## 百度网盘多端版本

设置页「百度网盘」支持用户主动进行跨设备备份：

- OAuth 登录通过腾讯云 CloudBase 云函数完成，百度 App Secret 只存在云函数环境变量中，不写入 APK；
- 云函数使用签名 state 校验回调，只向 App 传递 5 分钟有效的一次性 ticket，App 兑换后立即删除 ticket；
- access token / refresh token 由 Android Keystore 使用 AES-GCM 加密后保存在当前设备，并排除在 Android 系统备份之外；
- 「上传当前完整版本」先生成 `.lixingbackup`，再分片上传至百度网盘 `/apps/砺行` 应用目录；
- 网盘版本下载后仍需用户确认，恢复前继续自动创建 `before_restore` 本机恢复点；
- 当前采取手动上传、手动选择版本恢复，不做后台静默覆盖，避免两台设备同时修改时丢失数据。

#### 开源后别人能拿到我的数据吗？

**不能。** 开源的只有代码，不含任何用户数据：

- 网盘版本包只存在于**授权者本人**的百度账号里（`/apps/砺行` 应用目录）。任何人下载本项目重新安装，OAuth 授权的只会是**他自己**的百度网盘，与你的账号无关；
- 你的 access/refresh token 由 Android Keystore 硬件加密保存在你自己的手机上，不进备份、不进仓库、不上云；换设备需重新授权一次；
- 本仓库经审计不含任何打卡数据、密钥或个人文件（`app/debug.keystore` 为口令公开的调试密钥，见「开源许可」）；
- 需要你自己注意的唯一一点：`.lixingbackup` 版本包内容**未加密**，不要把它导出到公开分享目录或发给别人。

## WebDAV 多端同步（自动）

设置页「多端同步」支持通过任意 WebDAV 服务（坚果云、InfiniCloud、自建等）在多台设备间自动同步：

- **同步模型**：每台设备把本地变更写成云端独立的「设备变更文件」，同步时拉取其它设备的变更在本地合并，不直接改写对方文件，天然避免并发覆盖；
- **冲突解决**：Lamport 时钟定序，同字段后写者胜；删除以墓碑记录传播，不会被旧设备的迟到数据复活；照片列（打卡照片、AI 消息图片、餐食照片）不参与同步，各设备保留本地文件；
- **触发时机**：连接后立即同步一次；此后监听本地数据变更，操作停止 30 秒后自动同步；设置页可随时「立即同步」；手动同步撞上自动同步时直接提示不排队；
- **仅 Wi-Fi**：可限定只在非计费网络（Wi-Fi / 以太网）下自动同步，移动网络不偷跑流量；同步统计（上传/下载字节、最近时间）在设置页可见；
- **安全**：服务器地址、账号与应用密码由 Android Keystore 加密保存，不进入版本化备份；恢复备份/换机后需重新连接；
- **恢复点**：每次手动同步（以及首次自动同步）前自动创建 `before_sync` 本机恢复点（独立槽位，保留 3 份），同步异常可回退。

与「百度网盘版本」的关系：WebDAV 解决日常增量同步，百度网盘保留为手动整包备份/恢复通道；恢复成功并校验 SHA-256 之后，才会解锁「删除网盘旧副本」操作，避免误删。

## 墨墨背单词对接

- 认证：用户在墨墨 App「我的 → 更多设置 → 实验功能 → 开放 API」获取个人 Token，填入设置页，`Authorization: Bearer` 请求，无需 OAuth。
- 今日页显示「墨墨背单词」同步卡：今日已背 X/Y、学习时长、渐变进度条。
- 「同步打卡」把全天完成比例乘到每个背单词任务的目标上，走既有 [CheckInUseCase]，积分/连续/成就全部复用；墨墨今日累计背诵时长按增量计入英语科目投入，重复同步不会重复累加。
- **跟随多端同步自动打卡**（设置页开关，默认关闭）：开启后每次自动/手动同步会顺带拉取墨墨进度并打卡单词任务。安全边界：①「只增不减」——完成比例上升才推进任务，绝不撤销已有打卡与积分（手动按钮仍以墨墨为准，可回退）；② 两次执行至少间隔 15 分钟（DataStore 记录上次时间，恢复备份不清零）；③ 遵守「仅 Wi-Fi」开关，未配置 Token 的设备静默跳过；④ 打卡结果随 daily_task 正常跨设备同步。
- 接口：`get_study_progress`（进度）、`get_today_items`（今日单词）、`vocabulary/query`（查词）。
- 注意：实测返回带统一信封 `{"data":{...},"success":true}`，payload 在 `data` 里，  
  与 open.maimemo.com 文档画的顶层字段略有出入；DTO 用 `effective` 兼容两种形态。
- 默认关闭、不联网；token 存 DataStore，仅本机。


## AI 学习助手（可选联网）

一个默认关闭的可选功能：向助手提问、让它分析你的学习数据，并对计划修改给出**建议**。

- **架构（App 直连）**：App 直接调用任意 OpenAI 兼容接口（DeepSeek、月之暗面、智谱、OpenAI、OpenRouter 等）。「设置 → AI 学习助手」可保存多套模型配置并随时切换；每套分别保存配置名称、接口地址、模型名、API 密钥和是否支持多模态。配置集合与 API 密钥均由 Android Keystore 加密保存，不进入版本化备份，可逐条编辑或删除；换模型不需要改代码或部署任何服务。
- **模型列表随时可拉**：编辑已有配置时密钥框出于安全不回显（留空即沿用已保存的密钥），所以「获取模型列表」只看接口地址是否填了、并在密钥留空时自动回退到该配置已保存的密钥，随时可点、可重复点；密钥缺失且该配置从未存过密钥时按钮才会置灰。模型名输入框里已有文字也不影响拉取——下拉始终展示从 `/models` 拿到的**完整列表**（当前选中的那一项加粗），不会退化成「只显示输入框里那个名字」。拉取失败时保留上一次成功的列表，且连续点击只有最后一次请求的结果生效，不会被慢请求覆盖。
- **数据最小化**：上下文由模型按问题预判 + 你手动勾选（取并集），按种类（当前计划 / 今日任务 / 近期统计 / 英语积累 / 墨墨单词）裁剪，不包含照片、打卡备注原文、饮食记录或任何 Token。
- **个性化（称呼 / 城市）**：「设置 → AI 学习助手」可填「AI 对你的称呼」，回复会用这个称呼称呼你；「所在城市」不再手输，点一下按粗略定位（Wi-Fi / 基站级，只取城市名）自动填写，定位中与失败都有提示，不想用可随时清除、也可一直不填。两者连同**当前日期时间**一起注入系统提示词，所以「今天 / 本周 / 最近」这类时间问题以你的时区与当下时间为准；留空则不注入，行为与默认完全一致。定位只取大致城市、仅存本机、仅用于对话上下文。
- **会话持久化**：对话保存在本机数据库，助手页可随时开启新对话，历史对话列表支持回看、续聊、逐条删除；会话随版本化备份迁移，密钥不备份。发给模型的历史按**条数（24）与总字符（24000）双限**裁剪，只有真的超长才从最早的开始丢；自动续写产生的相邻回答片段会先合并成一条，模型看到的是完整回答而不是一串半截内容。
- **拍照问答**：助手输入框可连续拍摄或从相册多选题目（最多 9 张），路由由当前模型配置的「多模态模型」开关决定：开启时照片经 EXIF 方向校正、压缩（最长边 2048）后以 OpenAI 兼容图片内容块直接发给模型，由多模态模型自行识题作答，用户未输入文字时附带“先准确识别题目再细致解答”的默认指令；关闭时走完全离线的本地数学 OCR 管线，识别结果进入可编辑的「OCR 题目预览」，用户修正确认后发送，识别不到文字会明确提示。OCR 正文只作为模型输入，不在聊天气泡中显示；气泡仅保留用户输入和可点击放大的图片缩略图。OCR 模式永不上传图片；只有多模态模式会把照片上传给你配置的模型服务。聊天气泡里的缩略图点开后可看大图，支持双指捏合缩放（1~5 倍）、双击放大/还原、放大后单指拖动查看细节，越界自动回弹；未放大时点空白或下滑关闭。
- **本地数学 OCR（纯文本模型兜底）**：OpenCV 纠偏/增强 → Pix2Text MFD ONNX 公式区域检测（宽幅/窄幅等极端比例图片自动重叠分块，不再把整页压缩到 640×640 丢失细节）→ Pix2Text MFR ONNX 将公式识别为 LaTeX → ML Kit 中文 OCR 全文兜底。公式结果只替换“不含中文字形且通过质量门控（置信度、括号配对、无非法命令、长度与框宽高比匹配）”的文本区域，低置信或幻觉公式自动回退普通文字，不再整行涂白；表格经 OpenCV 网格线检测输出 Markdown 表格。模型与 ONNX Runtime 均随 APK 打包，全程离线推理。
- **公式渲染**：回答正文用 Markwon + JLatexMath 渲染（无 WebView、无 CDN）。不同服务商的公式定界符习惯不同，客户端会把 `$...$`、`\(...\)`、独占行的 `\[...\]` 统一归一化为渲染器支持的 `$$...$$`；代码块、行内代码与 `$5` 这类金额不会被误转换，此前只能显示公式源码的模型现在也能正常渲染。渲染前还会做一次环境兼容清洗：删除 JLatexMath 不支持的 `\tag{}`、`\hspace{}`、`\vspace{}` 和 `[6pt]` 这类行距标记，并为落单的 `\begin{aligned}...\end{aligned}` 补齐 `$$` 后转换成 `array` 环境，进一步降低公式以源码形式露出的概率。**发布注意**：JLatexMath 内部用 `Class.forName(...).newInstance()` 反射实例化 XML 预定义命令类，一旦被 R8 改名，真机渲染就会抛 `NullPointerException`（界面表现为「⚠ 公式无法渲染」占位框，且只有部分公式触发，极易误判成公式内容不兼容）。因此 `app/proguard-rules.pro` 必须整包保留 `org.scilab.forge.jlatexmath.**`；改动混淆规则后请真机复验一条 `cases` / `dfrac` 公式。
- **识题 / 校准模型可选**：设置里可为「拍题识题」和「饮食校准」各指定一个多模态配置。指定识题模型后，纯文本模型对话时先由多模态模型把照片题目转写进可编辑预览再作答，本地 OCR 仅在未指定时兜底；饮食校准模型用于餐食照片的名称、克重与营养估算，失败或未指定时回退端侧 TFLite。
- **公式自动换行**：回答渲染前用 JLatexMath 实测公式宽度，超宽的块级公式在顶层安全断点（对齐换行 → 逗号 → 关系符 → 加减号）拆成多行，超宽行内公式提升为块级，解决长公式右侧溢出被裁剪的问题；拆分具备环境感知——绝不在 `\begin{...}...\end{...}` 内部下刀，超宽的 `array`/`aligned` 环境按行解包成独立公式，跨行 `\left[…\right]`、`cases`/`pmatrix` 等矩阵整块保留不切；代码块与短公式不受影响。`Application.onCreate` 显式调用 `JLatexMathAndroid.init()`（Android 版 JLatexMath 从 assets 读取公式配置，必须先初始化），并用真实解析器做回归测试保证清洗/拆分产物可渲染。
- **思考强度可调**：每套模型配置可选低/中/高思考强度（默认低，快速直接作答；复杂题仍保留公式与推导）。
- **长回答自动续写（无固定轮数上限）**：公式推导这类费 token 的长回答撞到输出上限（`finish_reason=length`）时，客户端会自动发「继续」接着生成——只要每轮仍在产出实打实的长内容就一直续下去，文本与图片两条发送路径共用同一套逻辑。三道刹车防止失控（正常推导几段内自然写完，基本碰不到）：① 设置页「长回答自动续写」保护上限滑杆（默认 4 段，0 = 关闭自动续写）；② 单段几乎无新内容（< 200 字符）视为模型已收尾或打转，停止；③ 累计输出总长度保险丝。仍被截断收尾时会去掉悬空的加粗标记、补齐未闭合的公式块，并提示「发送继续可接着生成」。**续写时不再依赖滑动窗口取历史**：以本轮开始时的对话为锚，显式回传「原对话 + 已生成内容 + 续写指令」，多段输出写进同一条消息——否则每轮追加的片段会把最初的提问挤出窗口，模型失去锚点后就开始顺着「继续」自说自话；续写轮也不会重复联网（首轮已搜过，再搜既慢又可能与上文冲突）。
- **联网搜索**：默认开启，可在设置页关闭。时效性问题会自动带上搜索工具，由模型与服务端决定是否真的检索；想强制联网就打开对话页的「智能搜索」开关（会传 `tool_choice` 强制搜索）。
- **按服务商选对协议**：各家网关的联网方式并不统一——小米 MiMo 的 Responses 网关直接拒绝 `web_search`（HTTP 400 `responses_feature_not_supported`），而 DeepSeek 的 Chat Completions 只接受 `function` 类型的 tools（塞 `web_search` 会报 `unknown variant`）。客户端按端点自动分流：MiMo 一律走 Chat Completions（实测一次检索可拿到 25 条来源），其它服务改用各自支持的联网参数形态。
- **DeepSeek 的现状（2026-09 实测）**：它的服务端搜索曾在 V4-Flash 上可用（8 月初社区实测），但 9 月 10 日 V4.1 Flash 上线、旧 V4 Flash 下线后，新模型的 Responses 兼容层**忽略内置工具**（web search / file search / code interpreter 等）——请求返回 200，却不会真的搜索；Chat Completions 则始终拒绝该工具。官方 API Reference 仍写着"支持、服务端执行"，与实测及官方兼容性明细表相矛盾。这属于服务端能力变化，客户端请求格式没有问题，届时会如实说明本次是离线回答。需要联网请优先用 MiMo。
- **联网失败不再静默**：接口报错、模型不支持、地址拼错，回复里都会写明「联网搜索未生效，已改用离线回答（原因）」，而不是悄悄退回普通对话。更要紧的是能识别**「请求被接受、回答正常，但服务端压根没搜」**——这种情况现在会明确提示本次实际是离线回答。
- **联网搜索自检**：在**每个模型自己的编辑对话框**里（紧贴「联网搜索协议」那一行）点「测试联网搜索」，会用正在编辑的地址/模型/协议实测，同时试 Responses 与 Chat Completions 两种协议，报告 HTTP 状态、耗时、是否真的发起搜索、拿到几条来源，直接告诉你要把这套配置的协议改成哪个。排查联网问题时先点它。
- **只建议、不自动执行**：助手可以返回结构化动作——调整时段（含每时段「至少完成 N 项」的任务数）、调整任务模板、新增任务模板，以及今日任务的减量、换时段、单项跳过、整日请假或“仅保留指定任务”。方案会进入独立确认页，按「仅今日生效 / 长期计划」分区展示修改前后；用户逐项勾选后决定接受，或全部拒绝。整日请假使用单条短动作并在本地校验月度额度；“仅保留指定任务”也使用单条批量动作，避免任务较多时模型 JSON 被截断。跳过的任务卡从今日待办中隐藏，但记录仍保留在历史中；模板不变、明天照常生成。应用前自动创建 `before_ai_apply` 恢复点。模型未返回合法动作时客户端会明确提示“本次未修改任何数据”，不会把模型正文中的“已处理”当成执行结果。
- **确认入口可靠唤起**：动作协议是尾部的结构化 JSON，长回答撞上输出上限被截断、或模型在 JSON 前后裹了说明文字时，旧逻辑会整包丢弃导致「回答正常但确认按钮消失」。现在解析器按三级容错：整包解析 → 任意位置提取围栏块/`{`…`}` 子串 → 截断抢救（逐字符扫描、跳过字符串内的花括号，把已完整的动作条目恢复出来），并在截断时明确提示。
- **英语积累自动写入**：助手可以返回结构化英语动作——`ADD_ENGLISH_ENTRY` / `UPDATE_ENGLISH_ENTRY` / `DELETE_ENGLISH_ENTRY`。你可以直接输入、拍照（先识别再提炼）或让它从一段材料里总结好词好句，助手整理成条目后进入独立的「英语积累变更」确认页，逐条展示变更前/变更后，勾选确认后才写入本机数据库。本地会校验类型、内容长度、释义长度和条目是否存在；修改与删除只认上下文里真实出现的条目 id，模型猜的 id 会被拦下并要求重新生成。用户要求写英语积累但模型没给动作时，客户端会在正文前明确提示“本次没有写入任何内容”，不会让你误以为已保存。
- **硬边界**：不删除任何数据，不改已完成任务、积分与成就；唯一的例外是用户自己确认删除的英语积累条目。
- **熄屏/切后台保活**：回答生成期间启动 `dataSync` 前台服务（低优先级常驻通知，结束后自动停止），抬高进程优先级，显著降低熄屏或切后台后进程被冻结/查杀导致「没有任何输出」的概率；照片链路的转写/OCR 与回答阶段共用引用计数保活。
- **可选自建网关**：`cloudbase/ai-assistant/` 保留了把密钥放在云端的云函数方案（适合不想让密钥留在手机的人），当前 App 未内置该模式。

## 打卡与激励规则

- 时段内打卡 = 按时（满额分）；时段结束后当天内 = 迟到（5 折）；隔天补 = 补卡（3 折）。
- 关键任务（keystone）积分翻倍；量化任务超额另有奖励。
- 全天满勤 +30；连续 7/30/100 天分别 +50/+200/+600。
- 漏卡默认 -5（可在设置关闭）；连续记录按「当天完成率 ≥ 阈值（默认 60%）」延续。
- 断签可用每月补救卡保一次；请假不断签、不扣分。

## 自我承诺

「我的」页可以给未来的自己定一个硬指标，到期由 App 自动翻账本判定。  
核心是**预先承诺**：定约的那一刻是清醒的，兑现那天由不得自己解释。

- **立约**：选阶段或自定区间，并从「平均完成度 / 累计专注分钟 / 达标天数」中选择一个约束维度；
- **奖励**：可以同时设置积分和一项由自己兑现的现实奖励，例如看一场电影或买一本书；
- **进行中**：卡片常驻显示已过天数/总天数、当前指标值、目标值和差距。只在到期算一次的话它就只是个许愿池，中途看得见才推得动人；
- **到期结算**：状态翻成已达成/未达成，写入实际指标值与结算日；达成发放 `COMMITMENT_SETTLED` 积分并提示兑现自定义奖励；
- **判定口径**：平均完成度取区间 `day_record.completion_rate` 平均值；累计专注分钟取区间专注总和；达标天数统计 `isAchieved`；三者均排除请假和没有任务的日子；
- 平均完成度允许超过 100%，显示值向下取整，看到的数和结论保持一致；
- **未达成不扣分**，只是拿不到奖励。扣分会让人不敢立约，而立约本身是好行为；
- 区间内一天有效数据都没有（整段请假或没排任务）→ 判作废而非失败；主动放弃同样不扣分。

结算时机：`SettleDayUseCase.onAppStart()` 与每日 Worker 中都**排在当天结算之后**。  
承诺最后几天的 `day_record` 要等日结算写完才有终值，顺序反了会把未结算的尾巴当成 0，好的承诺被判失败。  
这个顺序由 `onAppStart()` 内部保证，调用方不需要关心。

幂等两层：到期查询只捞 `ACTIVE`，结算后状态变终态就再也捞不到；奖励积分带 `keyCommitment(id)` 幂等键，流水唯一索引兜底。

关键设计决策：

- **任务物化幂等**：`(date, template_id)` 唯一索引 + `INSERT OR IGNORE`，重复物化不产生重复任务。
- **积分防重发**：一次性奖励带 `dedupeKey`，流水表唯一索引兜底。
- **快照字段**：`DailyTaskEntity` 冗余科目名/色、时段时间，改模板不影响历史记录。
- **迁移不破坏**：`Migrations.ALL` 显式管理，禁用破坏性迁移。
- **积分以流水为准**：`totalPoints` 每次入账后从 `point_ledger` 重算，不增量累加，杜绝漂移/清零。
- **单词同步只认背单词**：按标题含「单词」过滤，避免误勾同为 MEMORIZE 的作文背诵/背大题。
- **打卡详情**：`daily_task` 增 `checkin_note`/`checkin_photo`（v1→v2 迁移），打卡可附文字+拍照，卡片显示 📝/📷。
- **时段任选完成**：`time_slot.required_task_count` 决定该时段最低完成数；0 表示全部完成，N 表示任选至少 N 项。达到最低数为 100%，超额完成可超过 100%（v2→v3 迁移）。
- **多维度立誓**：`commitment.metric` 支持平均完成度、累计专注分钟和达标天数，`custom_reward` 保存现实奖励（v3→v4 迁移）。
- **饮食分析**：`meal_record` 保存三餐/加餐照片路径、模型标签、置信度、份量和营养估算；AIY Food V1 模型随 APK 打包并完全端侧推理，食物名和克重可人工校正（v4→v5 迁移）。
- **英语积累**：`english_entry` 保存单词、短语或句子的英文原文、释义及创建/更新时间；类型可筛选，英文与释义可联合搜索，并随完整版本备份迁移（v5→v6 迁移）。
- **AI 图片消息**：助手可连续拍摄或从相册多选照片（单次最多 9 张）；多模态模式逐张发送图片，OCR 模式逐张提取文字。模型实际收到的完整正文与聊天界面展示文字分开保存，OCR 长文本默认隐藏；图片缩略图随消息和历史对话保存，点击可查看大图，并纳入版本化备份（v8→v9 迁移新增可空展示正文字段）。
- **多模态直送、本地 OCR 兜底**：多模态开关开启时照片经 EXIF 校正与压缩后直接发给模型；关闭时走本地数学 OCR 预览。两者共用同一发送/历史/备份链路，仅请求是否携带图片内容块不同。
- **文本优先的 OCR 融合**：本地 OCR 先取 ML Kit 全文，公式 LaTeX 只替换通过质量门控的非中文区域；异常结果回退普通文字，保证题干不被公式框吞掉。
- **公式定界符归一化**：渲染前把 `$...$` / `\(...\)` / `\[...\]` 统一转换为 `$$...$$`，兼容不同服务商的输出习惯；转换跳过代码块、行内代码与金额。
- **英语积累动作协议**：助手通过 `english_actions` 返回新增/修改/删除建议，与计划修改共用「只建议 + 本地校验 + 用户逐条确认」的链路；英文原文与释义的长度、条目 id 的真实性在客户端复核，非法动作被跳过并在界面上给出原因。

## 排程健康度

计划管理页内置「排程过满检测」：

- 一天学习总量超过 10 小时 → 提醒减量；
- 相邻时段之间空档 < 20 分钟 → 提醒留出休息；
- 单个时段 ≥ 3.5 小时 → 提醒中途休息。

理念：排得太满的计划执行不下去，坚持比强度重要。

## 应用内自动更新

- 启动时静默检查（仅 Wi-Fi、每天最多一次、可在设置关闭），发现新版本弹窗展示版本号、大小与更新日志；
- 确认后由系统 DownloadManager 下载（自带断点续传与通知），完成后校验云端清单的 SHA-256，通过才提示安装；
- 设置页「更新」卡片可随时手动检查：无新版本显示「✓ 已是最新版本」，失败显示原因；
- 版本清单由腾讯云 CloudBase 云函数 `update-check` 提供（国内直连），APK 托管在 GitHub Releases；清单支持内联 JSON / update.json 直链 / 代理 GitHub API 三种来源，见 `cloudbase/update-check/README.md`；
- 发布新版本：`docs/release.sh <版本号> <更新日志> <user/repo>` 一条命令完成构建、SHA-256、update.json 生成、Release 上传与 R8 mapping 归档。

## 维护与安全注意事项

- `.lixingbackup` 当前未做内容加密，只应放在用户自己的百度网盘应用目录或可信私有位置，禁止上传到公开分享目录；
- 多端共享是“手动创建新版本 + 手动选择恢复”，没有记录级合并，也不会自动判断哪台设备的数据更新；恢复会替换当前业务数据，但一定先创建恢复点；
- 百度凭证不进入版本包，因此每台新设备需要单独完成一次百度授权；断开连接会清除本机加密凭证，不会删除网盘文件；
- `BAIDU_CLIENT_SECRET` 只能保存在 CloudBase 云函数环境变量中。曾经公开过的 SecretKey/SignKey 必须轮换，旧 Cloudflare Worker 与 KV 确认稳定后应停用并移除密钥；
- CloudBase 免费体验版有资源点额度，应定期查看“套餐用量”；本项目请求量很小，但免费政策可能变化；
- 修改 CloudBase HTTP 域名、路由前缀或百度回调时，必须同步修改函数环境变量、百度开发者控制台和 Android `BAIDU_OAUTH_BASE_URL`；
- 更新云函数时应基于 `cloudbase/baidu-oauth/` 源码重新打包部署，保持自动安装依赖、`index.main`、路径透传和免身份认证；
- OAuth 成功页使用 `lixing://oauth/baidu` 唤回 App，URL 中只有短期 ticket，没有 access token 或 refresh token；不要把带 `ticket`/`state` 查询参数的完整地址发到聊天或截图中。

### 构建与发布

- **编译必须用 JDK 17/21**：机器上装了 JDK 25 时 Gradle 只会报 `What went wrong: 25.0.3`，几乎看不出是 JDK 问题；用 `GRADLE_USER_HOME` 下的 `gradle.properties` 指定 `org.gradle.java.home`，或导出 `JAVA_HOME`（本仓库开发机见「构建」章节的 `.gradle-local`）；
- **R8 不能混淆 JLatexMath**：该库靠反射加载预定义命令类，被改名后公式渲染会抛 `NullPointerException` 并显示占位框，`proguard-rules.pro` 里的 `-keep class org.scilab.forge.jlatexmath.** { *; }` 不能删；改动混淆规则后请真机点开一条含 `cases` 的公式复验；
- **每次发版都要归档 R8 mapping**：`docs/release.sh` 会自动复制到 `docs/mappings/mapping-v<版本>.txt`（该目录不入库），线上崩溃日志反混淆全靠它，不要跳过；
- **发版前确认能连上 GitHub**：Release 上传依赖 `gh`，国内需先开代理（如 Clash Verge）。注意只有后台服务进程在跑、主程序没启动时代理端口不会监听，此时 `gh auth status` 会误报 “token is invalid”，不必急着重登，先确认端口是否真的在监听；
- **清单里的 `apkUrl` 必须走加速镜像**：国内手机直连 GitHub 下载不可用，`docs/release.sh` 默认拼 `ghfast.top` 前缀，App 端另有多个镜像自动回退；
- **云函数 `update-check` 已切到 `UPDATE_MANIFEST_URL` 模式**，指向 `releases/latest/download/update.json`，发布新版本后无需再动云函数；
- **push ≠ 发版**：改完代码要记得 bump `versionCode` / `versionName` 并跑一次 `docs/release.sh`，否则清单还是旧版本号，手机上检查更新不会有任何变化。
