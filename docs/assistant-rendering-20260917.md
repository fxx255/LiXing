# AI 助手渲染与交互修复（2026-09-17）

## 公式

本次按桌面 1.jpg、2.jpg 展示的功率谱推导结构检查。截图中的错误占位只保留部分源码，无法从截图还原完整的原始回答；以下是测试确认的缺陷，不将其等同于已经取得那条原始回答的错误日志。

- 单行 `cases` 位于多行 `$$` 显示块内时，旧分支只检查本行的 `$$`，会再加一对定界符。现在与多行环境一样检查前面的显示块状态。
- 超宽公式拆行只跟踪普通括号，未完整跟踪 `\left|...\right|`、不可见定界符和命名定界符。现在拆行和行式环境解包都保护这些配对。
- 独立公式块之间的顶层 `\\` 应当被消费，不能成为孤立的前缀或尾缀。
- 解包 `aligned` 时不能把第一个 `{...}` 当作 `array` 的列规格删除。现在只有 `array` 才删除列规格。

回归覆盖公式源码守恒、矩阵/分段函数不被拆散、功率谱多行推导、不同宽度下真实 JLatexMath 解析。

## 长回答交互、续写遮挡

旧实现同时维护 Compose 固定高度和 TextView 自己的测量结果，且在布局流程外重复调用 `measure()`。表格首帧和公式异步加载后，Markwon 会通过 `setText()/requestLayout()` 请求重排，但固定高度可能保持陈旧。12 秒轮询还无法覆盖更晚完成的加载。

新实现让 AndroidView 的正常布局流程决定高度，去掉固定高度、定时测量和重复渲染。文本、表格依然使用既有 Markwon 插件，图片查看器和横向滚动功能保留。

思考面板作为反向列表的第 0 项独立占位，视觉上位于最新回答下方。生成结束时正文保持同一个组合位置，不再因 `busy` 分支切换销毁并重建整段 Markdown。

测试模拟 13 秒后公式变高/变矮，以及 6000 像素长文本后的图片点击、表格横向拖动。设备端还覆盖实际长正文、公式、插图与思考面板。

另核实：目前 `AnswerDelta` 只更新“正在生成”状态，正文在每轮响应解析完成后追加。因此不能把问题简单归因于“每个 token 都让正文轮询重启”。

## 绘图比例

主要原因在提示词：上一版要求曲线仅占纵轴约 1/3、范围约为数据跨度的 3 倍，且 `x²` 示例的定义域为 `[-5,5]`，却把 y 上限写成 15，与真实峰值 25 矛盾。

现在要求模型先计算峰谷、零点、非零基值和边界，再决定范围。非负功率谱以零基线为参照，通常给峰值上方少量余量；这一建议不是固定比例限制。保留常数项，不通过减掉基值或任意假设参数关系改变图形。

符号图使用关键符号刻度，并说明采样所用的示意参数比例。真实题目有给定参数时必须重新计算。原有 Canvas 渲染器的坐标映射、横向留白和数据采样未改动。设备预览还发现纵轴延伸线会进入标题区域，已将轴顶限制在绘图区之上预留的空白内，避免箭头穿过标题或落在画布外。

同时修复 `ticks:[]` 被解析成 `null` 的问题：现在明确的空数组表示隐藏刻度，字段省略仍表示自动刻度。检查设备导出的图还确认渲染器忽略了 `Axis.grid`，已补上两个轴独立的网格开关；`grid:false` 仅隐藏网格，不影响坐标轴、刻度、数据映射。这让模型能够实际执行干净的示意图排版。

提示词调整影响之后生成的图；历史图是已保存的 PNG，不会自动重新生成。设备测试导出的示例用于验证客户端绘图能力，并非调用模型得到的回答。
