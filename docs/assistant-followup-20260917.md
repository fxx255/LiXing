# 助手长思考、续写公式与高密度屏幕交互修复

## 取证范围

从已连接手机的 1.0.40（41）通过「保存本机版本」取得 2026-09-17 11:00 与 11:11 对话的原始正文。诊断备份及完整文本仅存放于被 Git 忽略的 `app/build` 下，不写入测试源码。读取并对照桌面 6.jpg、7.jpg。

手机拔走后只使用用户指定的 **MuMu模拟器12-1**（MuMu 实例 1，ADB `127.0.0.1:16416`）；没有在另一个模拟器上运行本轮测试。

## 长思考被当作回答

客户端原本在首轮、补充生成均只有 reasoning 时，将思考尾部加上「未完成的解题过程」作为正常 reply；ViewModel 另有从 reasoning 中提取示例 JSON 的逻辑。这两条路径都可能把未经确认的分析当成正式回答，现均移除。

补充生成使用低思考强度并增加输出预算至 16384；接口明确拒绝请求（HTTP 400）时以原有 8192 预算兼容重试一次。不会无限重试。补充请求保留原题图片，将图片放回原用户问题；不再次发起联网检索。若仍无最终答案，明确报告失败而不保存思考文本。若失败发生在续写轮，保存之前已取得的正文和图表。

同时修复 SSE 结束事件不含 `delta` 时丢失 `finish_reason`、收到 `[DONE]` 仍等待连接结束的问题，避免漏掉自动续写或无谓等待。取消操作不再被恢复请求的通用异常处理吞掉。

## 公式边界

- **7.jpg**：原文公式完整，但形如 `正文：$$` 开启跨行公式，下一行 `$$ 后续正文和行内公式` 关闭。旧拆行器只识别部分行首/行尾形态，将闭合符误当作新公式的开头。现在用同一套边界扫描规则处理跨行开启、关闭和余下正文，并跳过代码与转义定界符。
- **6.jpg**：已保存的消息在「结论」处已出现未闭合公式与重复字符；缺少原始逐轮网络响应，不能断言每个错误字符的来源。新回复保留各轮 JSON 解码后的原文与空白，拼接后再由渲染层统一规范化。续写要求重写被截断的末段并保留完整公式，合并时消除可确认的段落重叠。
- 对历史消息里「行内公式缺少闭合符、随后进入明确中文正文」的形态，渲染阶段局部补上边界，避免吞掉后文。不会擅自把重复的数字改成推测的正确公式，也不修改历史数据库。

## 图片点击与表格

关键复现条件是手机屏幕密度：同一份 11:00 原始回答在 MuMu 默认 540×960、220 dpi 下图片点击通过；改成手机的 1268×2756、520 dpi 后，实际触摸测试失败，回调计数为 0。只改变长气泡的圆角裁剪实现后，同一数据、同一屏幕参数的测试通过。

根因位于覆盖整条长回答的圆角 `Surface` 裁剪层的触摸命中路径，而非图片文件缺失。气泡现在绘制同样的圆角背景，不再给整条长回答建立该裁剪层；内容保留内边距，图片和 Markdown 自身仍有局部裁剪。用户气泡的文字前景色明确保留。没有改动图片查看器的缩放、翻页或关闭手势。
